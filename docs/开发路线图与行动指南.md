## 1. P0 —— 直接破坏体验的缺陷(建议 1-2 周内修复)

### P0-1 手牌无上限 + 布局溢出(TC-14 / TC-20)

- 【现状】`HandManager.draw()` 无限抽牌,30 回合不打牌 = 95 张;`Main.tscn` 的 `HandContainer` 只有 1100px 宽,单张卡 150px,第 4 关 13 张牌池总宽 2028px 必然溢出;牌库会无限循环重洗,无弃牌/烧牌机制。
- 【改动点】
  1. `src/player/HandManager.gd`:加 `max_hand`(建议 8),`draw()` 超限时改为"弃到弃牌堆"或"不抽并给提示";`fill_draw_pile()` 维护独立弃牌堆。
  2. `scenes/Main.gd` 的 `_refresh()`:卡片宽从 150 降到 ~100,或把手牌容器换成 `GridContainer`(自动换行)/ 包一层 `ScrollContainer`。
  3. `Main.tscn`:`HandContainer` 上方加手牌计数标签("手牌 5/8")。
- 【验收】更新 TC-14/TC-20 断言:30 回合后 `hand_size() <= 8`;13 张卡池场景不溢出且可滚动。
- 【设计参考】策划 3.1 节:手牌 5 张、可保留至多 3 张——用"回合结束弃到 3 张"作为保留机制的雏形,顺便根治溢出。

### P0-2 演化无法跳过 / 加速(TC-15)

- 【现状】`ChainReaction.execute_async()` 每次 Reaction 等 0.1s + 1 帧,200 连锁实机 18-45 秒,玩家只能干等,违背"连绵雨"的节奏感。
- 【改动点】
  1. `src/rules/ChainReaction.gd`:`execute_async(grid, pillars, frame_delay, speed)` 加 `speed` 参数(1x/4x/∞);∞ 时直接调同步 `execute()`。
  2. `src/main/GameManager.gd`:`execute()` 加 `speed` 透传;新增 `skip_evolution()` 信号供 UI。
  3. `scenes/Main.gd` + `Main.tscn`:执行演化按钮旁加"加速/跳过"按钮(演化阶段显示),跳过时一次性结算并直接刷最终画面。
- 【验收】TC-15 增加断言:同棋盘 `speed=∞` 时 200 连锁耗时 < 2s;UI 有跳过入口。
- 【连带】跳过后 `reaction_applied`/`flash_cell` 风暴可批量合并一次 `state_changed` 刷新,避免卡顿。

### P0-3 存档系统:三槽位 + 命名 + 覆盖确认 + 秒级时间戳(TC-13 系列)

- 【现状】`LevelManager.unlocked` 是内存字段,重启回到第 1 关;无任何存档。
- 【需求】(用户补充规格,替代原"仅解锁进度"方案)
  1. 三个存档槽;meta 区存全局通关进度(`unlocked`,删档不丢),槽位区存单局快照。
  2. 任意一次演化结束后可存档:选槽 + 命名。
  3. 覆盖非来源槽弹确认框;从该槽加载的本局再存同槽不提示(`loaded_from_slot` 标记);覆盖后标记更新为当前槽。
  4. 开始游戏必须选档或开新游戏(新增 `scenes/SaveSelect.tscn` 入口,`project.godot` main_scene 改指)。
  5. 主界面"调整存档"按钮:重命名 / 删除(需确认);删除来源槽后标记置 -1。
  6. 存档显示最后存档时间,精确到秒(`YYYY-MM-DD HH:MM:SS`)。
- 【改动点】
  1. 新建 `src/world/SaveManager.gd`:槽位读写(`user://save.cfg`)、全局 unlocked、快照序列化(Grid/柱/手牌/能量/回合/连锁/风/关卡)、`loaded_from_slot`、覆盖确认回调(可注入,便于测试)。
  2. `src/main/GameManager.gd`:`save_game(slot,name)` / `load_game(slot)` / 演化结束发 `evolution_finished`;`start_game` 支持从快照恢复。
  3. `scenes/SaveSelect.tscn` + `src/ui/SaveSelect.gd`(选档/新游戏/调整存档);`Main.gd` 加"存档"按钮与弹窗(选槽+命名+覆盖确认);`LevelSelect` 保留为"新游戏"入口。
- 【验收】TC-13 重写(存读一致、unlocked 独立持久化);新增 TC-13b(覆盖确认/来源槽静默/删除标记)、TC-13c(秒级时间戳、重命名/删除)、TC-13d(序列化 round-trip)。

### P0-4 全量贴图缩放审计(新增)

- 【现状】实测 `assets/` 全部 30 张 PNG:元素/状态/柱/尘贴图原生 1024×1024(部分 1254×1254)却绘制到 26-64px(约 1/16-1/20 缩小)+ 默认线性过滤 → 缩小后发糊;`Main.tscn` 面板背景变形:help_bg(1.5:1)→ 700×650(1.08:1)、gameover_bg(2.15:1)→ 700×150(4.67:1),ui_bg/level_select_bg 比例基本匹配;btn_*/card_frame/wind_icon 疑似未使用。
- 【改动点】`rendering/textures/canvas_textures/default_texture_filter` → Nearest;HelpPanel/GameOverPanel rect 对齐贴图宽高比(不变形、不越出视口);建"原生→绘制→比例"贴图台账,元素源图建议重出 64px 像素版;未使用资产移交 E-4 清理。
- 【验收】重写 TC-22(按真实原生尺寸断言)+ 新增 TC-22b(TextureRect 宽高比偏差 <5% 且不越出 1500×1000);人工验收 4 关/帮助/结算/关卡选择页无溢出、变形、过糊。

## 2. P1 —— 逻辑缺陷与鲁棒性(建议 1 个月内)

### P1-4 混沌判负不完整 + 水元素无解(TC-07)

- 【现状】`GameManager.chaos_check()` 只 `game_over.emit()` 不置 `game_ended`;水元素没有任何 EXTINCTION 牌,水 >50% 即必死且玩家无从反制——这是难度失衡,不是机制。
- 【改动点】
  1. `src/main/GameManager.gd` `chaos_check()`:`game_over.emit` 前后补 `game_ended = true; phase = Phase.EVOLVE`(与死寂路径一致)。
  2. 平衡二选一:给水加灭绝牌(如"蒸发" TRANSFORM:水+熔 → 汽+汽,或"干涸" EXTINCTION:水 ≥5 → 清空);或把水生成从 2/回合降到 1/回合并让 `CHAOS_ELEMENTS` 按关卡配置。
  3. `CHAOS_ELEMENTS` 改为来自关卡 JSON(`chaos_elements` 字段),不再硬编码。
- 【验收】TC-07 断言更新:`game_ended == true`;新牌有对应 `run_tests.gd` 用例;贪心基准 TC-06 仍 ≥100(不破坏难度)。

### P1-5 演化后选中残留,误触误打牌(TC-28b)

- 【现状】`GridRenderer.selected_card_idx` 在演化后不清空,玩家点网格会按旧索引把手牌[0] 打出并耗能量。
- 【改动点】`scenes/Main.gd` 的 `_on_execute()`:`grid_renderer.select_card(-1)`;`GameManager.execute()` 入口处再兜底置 `phase=EVOLVE` 时由 `_refresh()` 统一清空;`play_card` 前校验手牌索引仍有效。
- 【验收】TC-28b 断言更新:演化后 `selected_card_idx == -1`。

### P1-6 空/损坏 rules.json → 玩家死锁(TC-23b)

- 【现状】`_load_rules()` 失败返回空数组,开局手牌 0、`can_play_card()` 恒 false,无任何提示,只能回主菜单。
- 【改动点】`src/main/GameManager.gd`:
  1. `_load_rules()` 失败 → `push_error` + 发出 `game_over(false, "规则数据损坏,请重新下载游戏")`。
  2. 内置 `DEFAULT_RULES` 最小牌组(steamify/grow/extinct)作为降级后备,保证游戏可玩。
  3. 关卡 JSON 同理:尺寸/target 越界钳制(6-32 / 1-99999),字段缺失给默认值。
- 【验收】TC-23b 断言更新:空文件 → 降级牌组 3 张且可玩;损坏文件 → 明确失败提示而非静默死锁。

### P1-7 RuleCard.from_dict 非法字段崩溃(TC-25)

- 【现状】`Kind.get("XXX")` 返回 null 赋给 int 直接抛错,后续字段全部丢失。
- 【改动点】`src/rules/RuleCard.gd` `from_dict()`:kind 先查 `Kind` 是否含该 key,不含 → 该条跳过 + `push_warning`;radius/life/threshold 用 `clampi` 钳制;`Element/State.from_string` 已安全。
- 【验收】TC-25 断言更新:非法 kind 整条跳过且不崩溃,合法字段不受影响;`run_tests.gd` 补一条。

### P1-8 演化中切场景的协程竞态(TC-30c)

- 【现状】`execute()` 的 await 协程挂在 GameManager 上,切场景不中断;若此时 `start_game()` 重开,旧协程继续写新网格 → 潜在数据污染。
- 【改动点】`src/main/GameManager.gd`:保存 `_running` 协程引用,`start_game()` 先 `cancel` 旧协程;`execute()` 设/清 `_running`;`ChainReaction` 加 `cancelled` 标志,每轮循环检查。
- 【验收】TC-30c 扩展断言:切场景后旧演化中止,新局 `chain_total==0` 且不被污染。

## 3. P2 —— 玩法与语义完善(建议 1-2 个月)

### P2-9 FROZEN 语义统一(TC-30a)

- 【现状】FROZEN 只挡 trigger 格被转化,不挡 MULTIPLY 扩散目标——玩家直觉上"冻结的格子不该长东西"。
- 【改动点】`src/rules/Reaction.gd` `MULTIPLY` 分支:目标空格 `has_state(State.FROZEN)` 时跳过;同时在 `RuleEngine._match_cell` 里把 FROZEN 目标视为不可用格,避免产生空 reaction。
- 【验收】TC-30a 断言更新:FROZEN 空格不被填充;`run_tests.gd` 补对应用例。

### P2-10 MULTIPLY 时间戳语义(TC-30b)

- 【现状】`Reaction.apply()` 里新格 `placed_at_turn = 触发格.placed_at_turn + 1`,不是当前回合 → 世界规则(汽消散/土成岩)对增殖产物计时错误。
- 【改动点】`Reaction.apply(grid, turn)` 增加 `turn` 参数,`ChainReaction` 与测试统一传 `GameManager.turn`;所有新元素/新状态的 `placed_at_turn = turn`。
- 【验收】TC-30b 断言更新;全量回归两套测试。

### P2-11 音效层(策划 2.3 节)

- 【现状】零音效。
- 【改动点】
  1. `AudioStreamPlayer` 加在 Main 场景;每次 `reaction_applied` 播一个短"叮"。
  2. 音高随连锁数对数升阶(`pitch_scale = 1 + 0.05*log2(chain)`),里程碑(10/50/100/500/1000)换音色。
  3. 素材可用程序生成(简单方波/正弦合成)或免费像素音效包,先占位再替换。
- 【验收】人工验收 + `run_tests.gd` 不回归(音效不参与逻辑测试)。

### P2-12 粒子与演出

- 【现状】只有白块闪烁与静态贴图。
- 【改动点】
  1. `CPUParticles2D` 池:反应格爆点、尘漂移轨迹、陨石落点烟尘、祝福金光、燃烧火苗。
  2. 里程碑时屏幕边缘泛光(策划 2.3)。
  3. 连锁计数 pop 动画已存在(`ChainCounter.pop_anim`),加更大里程碑特效。
- 【验收】人工验收;16×16 满连锁下帧率 ≥ 30fps(用 TC-15 棋盘压测)。

### P2-13 卡牌系统强化:上限/保留/卡面资源化

- 【现状】卡面是 `Main.gd` 里手写的 `Button`,信息密度低、无图标、不可样式化。
- 【改动点】
  1. 新建 `scenes/RuleCardView.tscn`(卡框贴图 `card_frame.png` + 元素图标 + 类型色带),`RuleCardView.gd` 挂上去;`Main.gd` 改为实例化场景。
  2. 保留机制:回合结束时手牌上限 8,玩家自选弃到保留数(策划:保留至多 3 张的变体,按平衡调参)。
  3. 手牌悬停显示完整 tooltip(已有多行文本,统一排版)。
- 【验收】TC-20 宽度断言重算;卡面信息可读性人工验收。

### P2-14 预演 / 撤销(策划 4.1"我算到了")

- 【现状】放错柱子只能撤回,无法预知演化结果。
- 【改动点】
  1. 先做**撤销**:`GameManager` 每次 `end_turn()` 前把 `grid` 序列化成快照栈(元素+状态+pillars),"撤销"按钮回滚上一回合并退能量。
  2. 再做**预演**:消耗 1 能量,把当前布局丢进副本网格跑同步 `ChainReaction.execute()`,高亮显示预期 affected 格数/连锁估值。
- 【验收】撤销后状态完全一致(用快照哈希断言);预演不改变真实网格。

### P2-15 种子化 RNG + 回放/每日挑战

- 【现状】`randi()` 全局无种子,风/尘/天灾/生成不可复现,测试只能靠大量容差。
- 【改动点】
  1. 建 `src/world/Rng.gd` autoload 包装 `RandomNumberGenerator`,菜单可填种子(空 = 随机)。
  2. 所有 `randi()` 替换为 `Rng` 调用(含 `pick_random`/`shuffle` 用带种子的 rng)。
  3. 记录每局种子 → "复制种子"按钮;每日挑战 = 固定日期种子 + 固定关卡。
- 【验收】同种子两局演化完全一致(哈希比对);TC-06/TC-10 可改为固定种子精确断言,收紧容差。

### P2-16 新内容:第 5 关与占位机制

- 【现状】`STEAMED`/`ASH` 状态、`FROZEN` 加冻、`trigger_state` 字段、`contact_coord` 字段均未使用——引擎已预留扩展位。
- 【改动点】(数据驱动,基本不动引擎)
  1. 第 5 关(如 18×18"深渊"):用 `trigger_state` 做状态触发牌(如"带电:汽接触带电水 → 生成光尘"),启用 STEAMED/ASH 状态。
  2. FROZEN 加冻:冰邻水 → 水加 FROZEN(新世界规则)。
  3. 新天灾:酸雨(清状态)/ 磁暴(随机移动柱子)。
- 【验收】新牌新关卡只改 JSON + 枚举,引擎零改动(回归两套测试)。

### P2-17 关卡目标多样性(策划 3.2)

- 【改动点】关卡 JSON 加 `goals` 数组:累计目标 / 单次演化峰值 / 限定回合 / 禁用元素;通关界面按目标逐项打勾,星级评价(1-3 星)。
- 【验收】每项目标有对应断言;TC-06 作为难度基准保留。

## 4. P3 —— 工程与长期(持续进行)

### E-1 世界规则拆分

- 【现状】`GameManager._world_rules()` 120 行单体,第 4 关天灾硬编码在里层。

### E-3 UI 资源化与国际化

- 【现状】`LevelSelect` 纯代码建 UI;中文文案散落于代码/tscn/卡牌 tooltip。
