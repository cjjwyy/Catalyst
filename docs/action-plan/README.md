## 0. 目标与原则

1. **先修体验后加内容**:P0/P1 缺陷修复完之前,不做新玩法。
2. **测试先行**:每个任务先更新/新增测试断言,再改实现;两套测试(headless)必须全绿。
3. **数据驱动不动引擎**:新牌/关卡只改 JSON + 枚举(项目既有原则)。
4. **每任务一个 commit**:消息带任务编号(如 `fix(hand): 手牌上限与溢出 T1.2`)。
5. **平衡改动必须重跑基准**:TC-06(第 1 关贪心 20 回合 ≥100)与 TC-16(振荡终止)不得回归。
6. **文档随代码同步**:每阶段收尾更新 README 已知问题、路线图状态、AGENTS.md(如需)。

## 3. 执行约定

- **完成定义(DoD)**:改动点落地 + 对应测试断言更新且 headless 全绿 + commit 含任务编号 + 本文件勾选 + (如影响玩法)README 已知问题同步。
- **测试运行**:
  ```powershell
  # 核心自检: Godot 启动时自动跑,或
  godot --headless --path . --script res://tests/whitebox_tests.gd
  godot --headless --path . --script res://tests/whitebox_tests.gd -- --filter=TC-06
  ```
- **"现状记录"用例的更新纪律**:TC-30a / TC-30b 仍断言的是"有缺陷的行为";对应任务修复后,**必须先改断言再改实现**,防止测试静默变绿。
- **顺序依赖**:阶段 1 → 2 → 3 顺序执行;阶段 4 可与阶段 3 尾部任务并行(标注于任务卡)。
